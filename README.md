# 次軌道載具設計工作單

互動式教學工作單,說明設計一個「太空港到太空港」的次軌道飛行系統時,
工程因子如何彼此耦合 —— 以及模擬工具的能力邊界在哪裡。

給大學工程背景的學生使用。

## 定位

這是**長程次軌道／高超音速跨洲飛行**的概念分析與模擬工具邊界辨識教材,
**不是**民用次軌道觀光飛行器(80–120 km 高度、數百公里射程)的設計模型,
也不是「次軌道載具設計計算器」。

預設航線 13,109 km、遠地點約 1,189 km,尺度接近洲際彈道或全球次軌道運輸。
所有數值是一階概念估算,**不是設計值**。

## 這頁想解決的教學問題

講這個題目最容易做成「公式清單 + 靜態圖表」,學生會把每個公式當成獨立的
知識點記下來。但真正的設計困難在於**這些因子彼此耦合,不能各自最佳化**。

所以整頁的骨幹是一條推導鏈:七個設計變數(射程、升阻比、兩節比衝、
Δv 分配、推重比、損失假設),動任何一個,七個步驟的數字同時重算。

    射程 → 中心角 → 純彈道所需速度 → 加入機翼的分段代理模型
         → Δv 預算 → 質量比(指數關係)→ 燃燒時間與分離時刻
         → 再入條件與工具邊界

## 三個刻意安排的教學時刻

| 針對的迷思 | 呈現方式 |
|---|---|
| 「加機翼一定有利」 | 全程滑翔曲線與純彈道基準線在 **L/D ≈ 1.61** 交會;低於此機翼是淨負擔 |
| 低估 Δv 對質量比的敏感度 | 對數縱軸上兩節式是一條直線;旁邊是同樣 Δv 用單節做的曲線 |
| 以為模擬工具涵蓋全程 | 軌跡剖面上的**再入減速帶**沒有任何現成模型涵蓋,畫得和其他三段一樣顯眼 |

第三項是這頁最想傳達的東西。工程模擬裡「模型邊界」的存在是常態,
但教材通常只給一條看起來完美的軌跡,學生因此不知道要去問邊界在哪。

## 四層狀態

頁面把設計點的狀態分開顯示,因為這四件事常被混為一談:

| 層 | 判定 |
|---|---|
| 數學可算 | 所有輸出為有限值 |
| 模型適用 | 平衡滑翔未退化、短弧解成立、推重比 > 1、質量比 < 20 : 1 |
| 模擬工具 | 所需速度是否超出航段求解器的收斂範圍 |
| 工程可行 | **恆為「未驗證」** |

第四層刻意寫死,不隨參數變化 —— 無論參數怎麼調,要判斷可行性都還需要
上升段軌跡最佳化、含阻力與升力的六自由度再入積分、氣動係數資料庫、
熱防護與結構分析,以及控制系統設計。本頁一項都沒有。

## 計算依據

最小能量彈道解(球形地球、無阻力)、Eggers 理想化平衡滑翔射程、
齊奧爾科夫斯基方程、Sutton–Graves 熱通量比例式的速度項。

每一條公式的假設、適用範圍與失準處寫在
[`web/設計與計算原理.md`](web/設計與計算原理.md),
包含兩個在撰寫該文件時才發現的數值錯誤(地球半徑常數不一致、
損益平衡點畫在一條永遠不會相交的曲線上)。

## 執行

工作單是單檔 HTML,可直接用瀏覽器開啟
[`web/suborbital_workbench.html`](web/suborbital_workbench.html),
不需要任何伺服器。

Streamlit 版本只是部署外殼(取得公開網址、提供下載),
不是原生 Streamlit app —— 理由與取捨寫在 `streamlit_app.py` 的 docstring。

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

### 部署到 Streamlit Community Cloud

```
Branch          main
Main file path  streamlit_app.py
```

相依由根目錄的 `requirements.txt` 自動讀取(只有 `streamlit` 一項),
不需要在 Advanced settings 另行指定。
