## 第一部分：設計原理

### 1.1 這頁要解決的教學問題

一般在講次軌道載具設計時，最容易做成「公式清單 + 靜態圖表」。那樣的問題是：
學生會把每個公式當成獨立的知識點記下來，而真正的設計困難在於**這些因子彼此耦合，
不能各自最佳化**。

所以這頁的單一目標是：

> 讓學生動一個設計變數，親眼看到整條推導鏈跟著動。

射程加 10%，所需速度不是加 10%；速度加一點，質量比跳一大截；
把升阻比調到 1.0，機翼從資產變成負債。這些都不是讀得到的，是要動手才會有的直覺。

### 1.2 為什麼用「推導鏈」當骨幹

頁面第 01 節是七個滑桿加七個步驟，每個步驟一列。這個結構刻意模仿**任務分析工作單**
的樣子，而不是儀表板。理由：

- **順序帶有資訊。** 步驟 1→7 是真實的設計推導順序，不是任意排版。
  編號在這裡是內容，不是裝飾。
- **每一步都露出公式。** 學生看得到那一步的物理依據，而不只是結果。
- **每一步都有「為什麼」。** 最後一行說明這個量會和誰打架，這是耦合關係的所在。

### 1.3 三個刻意安排的教學時刻

| 位置 | 針對的迷思 | 呈現方式 |
|---|---|---|
| 機翼門檻曲線 | 「加機翼一定有利」 | 助推滑翔曲線與純彈道基準線的交點，L/D = 1.61 |
| 工具邊界是設計指標 | 以為模擬限制與設計無關 | 同一張圖上，L/D = 6.54 時所需速度降到求解上限以下，**接縫消失** |
| 質量比的指數牆 | 低估 Δv 對質量比的敏感度 | 對數縱軸，兩節 vs 單節，20 : 1 紅色禁區 |
| 軌跡剖面的接縫 | 以為模擬工具涵蓋全程 | 再入減速帶畫成紅色虛線區，與其他三段同樣顯眼 |

第三項是這頁最想傳達的東西。工程模擬裡「模型邊界」的存在是常態，
但教材通常只給一條看起來完美的軌跡，學生因此不知道要去問邊界在哪。

### 1.4 機翼門檻曲線的一個修正（值得記下來）

第一版把損益平衡點畫在**最佳三段式**曲線與純彈道基準線的交點上。
那個標記**永遠不會出現**，因為：

```
optimum(range, L/D) = min over f of  max( v_ballistic(f·range), v_glide((1−f)·range) )
```

`f = 1`（完全不用機翼）本身就是掃描裡的候選解，所以最佳解**必然 ≤ 純彈道**，
兩條線不可能相交。

修正後改用**全程滑翔**曲線找交點（L/D = 1.608）。而這個錯誤本身變成了頁面上的
一個教學點：

> 看最佳化後的曲線，看不出某個設計要素划不划算 ——
> 最佳化器永遠留著「不用它」的選項。要和「不用它」的單一設計直接比才看得出來。

**後續**：那個 `optimum()` 代理模型本身在第二次更正中被整個移除了（見 2.4），
因為它產出的軌跡遠地點 1,130 km、不可飛。現在圖上畫的是助推滑翔曲線，
與純彈道基準線確實會相交（L/D 1.61），上面這個陷阱不再存在 ——
但它記錄的教訓仍然成立，所以保留。

只開放「設計者真的可以選」的量。像大氣密度、重力常數這種不是選擇的，不給滑桿。

| 變數 | 範圍 | 為什麼是這個範圍 |

- **沒有把上升段畫成計算結果。** 那需要軌跡最佳化（見 2.10），所以畫成示意曲線並標明。

## 第二部分：計算原理

### 2.0 常數

```js
RE = 6378137.0 m        // WGS84 赤道半徑
MU = 3.986004418e14 m³/s²
G0 = 9.80665 m/s²
發射點緯度 22.0620°N，大圓方位 35.335°

KARMAN   = 100,000 m    // 卡門線：助推段的目標熄火高度
GAMMA_BO = 2°           // 熄火飛行路徑角。淺角度是助推滑翔的關鍵
CL_GLIDE = 0.8          // 滑翔段配平升力係數
```

> **一個曾經不一致的地方。**
> 頁面第一版用平均半徑 6,371,000 m，而 repo 的 `spaceport_analysis.py` 用
> WGS84 赤道半徑 6,378,137 m。差 0.11%，傳播成 v_bo 差 0.075%、遠地點差 0.2%。
> 兩邊的數字都「合理」，但網頁與分析模組給出**不同答案**，那是不能接受的。
> 現已統一為 6,378,137 m，四項對照全部降到機器精度（相對差 `0.00e+00`）。
>
> 附帶說明：用赤道半徑當球體半徑，在 22–30°N 的航線上會略微高估大圓距離。
> 這是刻意接受的簡化 —— 與分析模組一致比絕對精確更重要。

### 2.1 射程 → 中心角

```
θ = R / R_E
```

頁面把射程當輸入，直接除以地球半徑得中心角。13,109.3 km → 117.76°，
已是地球周長的 33%，球面幾何不能再用平面近似。

### 2.2 最小能量彈道

起點與落點同半徑、球形地球、無阻力的經典解：

```
v² / (g·R_E) = 2·sin(θ/2) / (1 + sin(θ/2)）
γ = 45° − θ/4
```

其中 `g = MU / R_E²`。這給出**最省速度**的彈道，也是「不用機翼」的基準線。

遠地點與飛行時間由軌道元素推導，不是近似公式：

```
ε = v²/2 − μ/r₀              比能
a = −μ / (2ε)                半長軸
h = r₀·v·cos γ               角動量
p = h²/μ                     半正焦弦
e = √(1 − p/a)               離心率
apogee = a(1+e) − R_E
cos ν₁ = (p/r₀ − 1)/e        發射點真近點角
E₁ = 2·atan[√((1−e)/(1+e))·tan(ν₁/2)]     偏近點角
M₁ = E₁ − e·sin E₁                         平近點角
TOF = 2(π − M₁) / √(μ/a³)
```

**假設與失準處**

- 二體、球形地球、無大氣、起落點**同半徑**、瞬時脈衝。
- 取**短弧解**（排除同樣滿足射程的長弧解）。
- **不含地球自轉**造成的慣性座標差異；自轉只在 2.5 的 Δv 預算裡以助益項出現，
  沒有進入彈道幾何。
- 真實載具熄火在約 100 km 而非地表，且再入時有阻力。

它不是含地球自轉、大氣與升力控制的實際彈道，只是「不用機翼」的比較基準。

### 2.3 理想化平衡滑翔射程（Eggers）

```
R_glide = (L/D) · (R_E / 2) · ln[ 1 / (1 − (v/v_c)²) ]
```

`v_c = √(μ/R_E) = 7,905 m/s`（**地表**圓軌道速度，不是 200 km 軌道速度）。

> **這是從再入點算起的總滑翔射程，不是可以疊加在彈道射程上的增量。**
> 把兩者相加會嚴重誇大機翼效益 —— 本專案曾經犯過這個錯，
> 把 L/D 2.0 的效益從 0.34 km/s 誇大成 1.1 km/s。

反解（已知射程求所需再入速度）：

```
v = v_c · √( 1 − exp[ −R / ((L/D)·R_E/2) ] )
```

**假設**：等升阻比、升力與（重力 − 離心力）平衡、指數大氣、球形地球。

> 本式是**理想化平衡滑翔射程估算**，不等同於包含真實阻力、升力係數、
> 攻角限制與熱流約束的再入軌跡積分。頁面上的標籤已相應改為
> 「理想化平衡滑翔」，避免讀者把它當成真實滑翔距離。

**模型退化點（實測）**：當 `v → v_c` 時，升力恰好抵消重力，載具不再下降，
平衡滑翔解**退化**。實測 L/D 0.5、射程 16,000 km 時 `v/v_c = 1.0000` ——
數值有限，但物理上沒有意義。頁面因此加入 `v/v_c > 0.95` 的模型適用性警示
（見第五部分的三層狀態）。

**與「不含氣動阻力損失」的關係（容易混淆，特此澄清）**：
第七部分限制條列裡的「不含氣動阻力損失」指的是 **2.5 Δv 預算中上升段的阻力損失**，
不是說滑翔段沒有阻力。Eggers 模型本身正是透過理想化的升阻關係描述能量耗散，
它**有**阻力，只是以固定 L/D 的形式高度簡化。

### 2.4 淺角度助推滑翔（取代了分段代理模型）

熄火速度**直接由全程滑翔射程反解**，熄火點放在卡門線附近、角度壓低，
之後全程靠升力：

```
v_bo = v_c · √( 1 − exp[ −R / ((L/D)·R_E/2) ] )       全程滑翔反解
熄火狀態 = ( R_E + 100 km,  v_bo,  γ = 2° )
```

遠地點由熄火狀態的軌道元素求出（`orbitFromBurnout`，式同 2.2 但起點不在地表）。

#### 為什麼換掉舊模型

舊版 `optimum()` 把射程拆成「大氣層外滑行」+「平衡滑翔」，各自求所需速度
取較大者，再掃描分配比例取最小。它算出 L/D 2.0 時 v_bo = 6,406 m/s，
比全程滑翔的 7,382 便宜近一千。

**那個便宜是假的。** 最小能量彈道的熄火角是 `γ = 45° − θ/4`，射程愈短角度
愈陡 —— 6,292 km 的滑行段對應 **γ = 30.9°**，把載具拋到 **1,130 km**，
是卡門線的 11.3 倍。那條軌跡：

- 對無翼彈頭確實最省（那正是「最小能量」的定義）
- 對有翼載具是白爬升，而且再入角太陡、熱負荷集中在很短的時間內
- 沒有任何乘波／滑翔飛行器會那樣飛

改成淺角度熄火後（實測）：

| γ_bo | 遠地點 |
|---|---|
| 0° | 100 km |
| **2°（採用）** | **130 km**（L/D 2.0）／ **107 km**（L/D 4.0） |
| 5° | 269 km |
| 12° | 808 km |

#### 代價，以及怎麼賺回來

助推滑翔在**同一個升阻比下比舊模型貴**，因為舊模型的便宜是幻覺。
要把 Δv 賺回來，靠的是提高升阻比，不是拋高彈道：

| 架構 | v_bo | 總質量比 |
|---|---|---|
| 舊：分段代理模型（不可飛） | 6,406 m/s | 13.5 : 1 |
| 助推滑翔 L/D 2.0 | 7,382 m/s | 18.8 : 1 |
| **助推滑翔 L/D 4.0（採用）** | **6,335 m/s** | **13.2 : 1** |
| 助推滑翔 L/D 6.54 | 5,400 m/s | 9.6 : 1 |
| 全程純彈道（無翼） | 7,593 m/s | 20.2 : 1 |

**L/D 4.0 就把假軌跡宣稱的省油全部賺回來了**，而且是真的。
設計點因此從 2.0 改為 4.0 —— 那是實用乘波體的範圍。

#### 卡門線是「進入」高度，不是滑翔高度

平衡滑翔要升力等於**離心解除後**的有效重量：

```
½·ρ·v²·C_L = (W/S)·g·(1 − v²/v_c²)
```

離心解除那一項是關鍵。v = 7,400 m/s 時有效重量只剩 **12.4%**，
所以滑翔高度比直覺高很多：

| 速度 | 有效重量 | 平衡滑翔高度（W/S 250） |
|---|---|---|
| 7,400 m/s | 12.4% | 80.8 km |
| 6,500 m/s | 32.4% | 73.1 km |
| 5,400 m/s | 53.3% | 67.1 km |
| 2,500 m/s | 90.0% | 50.8 km |

載具在 100 km 熄火後**下沉到 70–85 km 才建立平衡滑翔**，
再隨速度衰減逐步下降。這獨立驗證了原本選用的交接高度量級；
現在交接高度不再是手選的，而是由這條式子解出（L/D 4.0 時為 67.1 km）。

#### 工具邊界變成設計指標

真空弧只能到載具降至平衡滑翔高度為止 —— 之後靠升力維持的滑翔，
彈道傳播器表示不了（它是真空橢圓，沒有升力就會掉下來）。
而 Aviator 的航段求解在 5,400 m/s 以上不收斂。中間那一段沒有模型涵蓋：

| L/D | 真空弧 | **無模型涵蓋** | Aviator 段 |
|---|---|---|---|
| 4.0 | 1,327 km (10%) | **3,765 km (29%)** | 8,017 km (61%) |
| 6.54 | 843 km (6%) | **0** | 12,266 km (94%) |

**L/D = 6.54 時接縫消失**，整條任務可端對端模擬。
這是本頁最想傳達的一件事：工具邊界不是事後才發現的限制，
而是可以寫進規格的**設計指標**。

### 2.5 Δv 預算

```
Δv_total = v_bo + 損失 − 自轉助益
自轉助益 = 465.1 · cos(緯度) · sin(方位)
```

465.1 m/s 是赤道自轉速度。緯度 22.06°、方位 35.3° → **249 m/s**。
這是選址與發射方位的工程理由：往東發射可借自轉，往西要倒扣。

**座標定義**：方位角採「**自正北順時針**」，正東為 90°、正南 180°、正西 270°。
此處使用的是**大圓航線在發射點的初始方位**（不是固定不變的航向 ——
大圓航線的方位沿途會改變）。

損失（重力 + 氣動 + 轉向）是**輸入假設**，不是算出來的。
頁面預設 1,600 m/s，並在滑桿說明裡標出入軌任務的公認區間 1,500–2,000。

### 2.6 質量比（齊奧爾科夫斯基）

```
R = exp( Δv / (Isp · g₀) )
R_total = R₁ · R₂
```

分配：`Δv₁ = split · Δv_total`，`Δv₂ = (1 − split) · Δv_total`。

指數牆那張圖的縱軸是對數的 —— **直線代表指數成長**。
灰虛線是「同樣 Δv 用單節做」，用來說明為什麼必須分節。

### 2.7 燃燒時間與分離時刻

```
ṁ = F / (Isp·g₀)              質量流率
F = (T/W) · m₀ · g₀           推力由起飛推重比定義
⇒ ṁ = (T/W) · m₀ / Isp

m_p = m₀ · (1 − 1/R)          推進劑質量

⇒ t_burn = m_p / ṁ = Isp · (1 − 1/R) / (T/W)
```

**`m₀` 消掉了。** 分離時刻與載具絕對大小無關，只取決於 Isp、Δv 分配、推重比。
這對概念設計很重要 —— 那三個量都是設計選擇，而總質量此時還不知道。

**成立條件**：定推力、定比衝、起飛推重比固定、理想火箭方程。
真實級段有節流（Falcon 9 在最大動壓與最大過載時都會降推力）、推力隨高度變化
（海平面與真空推力不同）以及殘留推進劑，因此這個值**不可直接視為實際級段燃燒時間**。

第二節推重比固定 0.8（上面級常見值，未開放為滑桿）；
分離到二節點火的滑行固定 6 s。

**驗證**：預設設計點得到 T+180 s。真實兩節式液體載具的第一節燃燒時間
（Falcon 9 162 s、Atlas V 253 s、Delta IV 245 s、Antares 205 s）區間是 162–253 s，
本設計落在區間內。這是外部基準，比公式自洽更有說服力。

### 2.8 速度三次方熱負荷指標（原稱「再入熱通量」）

Sutton–Graves 的比例形式是：

```
q ∝ √ρ · v³
```

但頁面的實作**只取速度項**：

```
指標 = (v_entry / v_c)³        v_c = 7,905 m/s
```

> **公式與實作不一致，已修正敘述（依審查意見 4.3）。**
> `√ρ` 那一項在實作裡被丟掉了，等於假設密度相同。先前頁面標籤寫
> 「熱通量（對軌道再入）」，會讓人以為那是完整的 Sutton–Graves 熱通量比。
> 現已改名為「**速度三次方熱負荷指標**」，並在公式旁註明假設密度與鼻錐半徑相同。

絕對值需要鼻錐半徑與大氣模型，本頁不聲稱算得出來。
教學重點是那個**三次方** —— 再入速度降 10%，指標降約 27%。

### 2.9 等效阻力減速量級（原稱「再入減速過載」）

```
a ≈ g / (L/D)
```

**理想平衡滑翔下的減速量級估算。** L/D 2.0 → 0.5 g。

> **這不是乘員過載，也不是結構最大過載（依審查意見 4.4 修正標籤）。**
> 峰值過載發生在再入走廊的特定時段，要由含阻力的軌跡積分得出，
> 而本式只給平衡狀態下的量級。頁面標籤已改為「等效阻力減速量級」。
頁面同時指出反向的張力：減速愈緩和，在高熱流區待得愈久 ——
**熱負荷總量與峰值是兩個不同的約束**。

### 2.10 軌跡剖面的繪製方法

哪些是計算、哪些是示意，必須分清楚：

| 段落 | 繪製依據 | 性質 |
|---|---|---|
| 動力上升段 | `alt = 100 km · f^1.6`，水平跨距取 min(8%·射程, 900 km) | **示意曲線** |
| 真空弧 | 熄火狀態的圓錐曲線 `r = p/(1 + e·cos ν)`，掃到降至平衡滑翔高度為止 | **計算結果** |
| 高速滑翔（無模型） | 寬度由 L/D 決定，高度同樣由平衡滑翔解出，畫成虛線 | **計算結果，但無模型涵蓋** |
| 平衡滑翔段 | 每一點的高度由 `equilibriumGlideAlt(v)` 解出 | **計算結果** |

滑翔段的高度**不再是內插的**。舊版用 `frac = (v/v₀)²` 在交接高度與進場高度
之間內插，那只是一條形狀合理的曲線；現在每一點都由「升力 = 離心解除後的
有效重量」解出，有物理依據。

上升段之所以是示意的：真實上升段要同時滿足熄火速度、飛行路徑角、高度三個條件，
而那是軌跡最佳化問題。本專案的 `spaceport_ascent.py` 試過用單一自由度
（俯仰踢角）的重力轉彎積分去收斂，失敗了（熄火高度算出 649 km，
而設計值是 100 km），並且損失模型在入軌基準案例上只算出 655 m/s，
遠低於公認的 1,500–2,000。**那個積分器沒有通過基準，所以不用來畫圖，也不用來宣稱驗證。**

三個階段的水平分配：上升段佔一段固定跨距，其餘按最佳解的彈道/滑翔比例分配。
第一版把上升段**疊加**在彈道段之外，導致滑翔段畫出來的長度比計算結果短掉一整個上升段。

## 第五部分：三層狀態與極端案例測試

### 5.1 為什麼要分三層

「公式算得出有限值」「模型在這個參數範圍內成立」「工程上做得出來」
是三件不同的事，但常被混為一談。頁面因此把設計點的狀態分成四列顯示：

| 層 | 判定依據 |
|---|---|
| **數學可算** | 所有輸出為有限值（`Number.isFinite`） |
| **模型適用** | `v/v_c < 0.95`（Eggers 未退化）、中心角 < 170°（短弧解成立）、T/W > 1、質量比 < 20 : 1 |
| **模擬工具** | 所需 `v_bo` 是否超出 Aviator 航段求解上限 5,400 m/s |
| **工程可行** | **恆為「未驗證」** —— 本頁全部是一階解析估算 |

第四列刻意寫死為「未驗證」，不隨參數變化。因為無論參數怎麼調，
要判斷可行性都還需要上升段軌跡最佳化、含阻力與升力的六自由度再入積分、
氣動係數資料庫、熱防護與結構分析，以及控制系統設計 —— 這些本頁一項都沒有。

### 5.2 極端案例掃描（實測結果）

用 Python 複刻頁面的演算法，掃過所有設計變數的角落組合：

```
射程   2,000 / 2,000.1 / 13,109.3 / 16,000 km
L/D    0.5 / 1.0 / 2.0 / 4.0
Isp1   240 / 340 s          Isp2   280 / 460 s
分配   0.40 / 0.62 / 0.80   T/W    1.05 / 1.80
損失   1,000 / 2,600 m/s
                                    共 768 組
```

| 檢查項目 | 結果 |
|---|---|
| 非有限值（NaN / Infinity） | **0 筆** |
| 總質量比 > 10,000 : 1 | 0 筆 |
| 燃燒時間 > 2,000 s | 0 筆 |
| 所需 `v_bo` > `v_c` | 0 筆 |

**但掃描抓到一個更重要的東西**：L/D 0.5、射程 16,000 km 時，
全程滑翔所需速度 = 7,905.2 m/s，`v/v_c = 1.0000`。數值有限，
**但物理上沒有意義** —— 平衡滑翔解在此退化（見 2.3）。

所以該加的不是 NaN 防護，而是**模型適用範圍防護**。這正是三層狀態第二層的由來。
NaN 防護仍然加了（成本近乎零，而一個長得像數字的 `NaN` 會讓人誤以為那是結果），
非有限值一律顯示為「無解」。

### 5.3 θ → 0 的邊界

`drawProfile` 在滑行佔比為 0 時會以 `ballistic(1 m / R_E)` 取值。
實測該極限：`v = 3.130 m/s`、`apogee = 0.2 m`、`TOF = 0.454 s`、
`e = 0.999999922`，全部有限。`acos` 的引數已做 `[-1, 1]` 夾制。

### 6.4 第二次更正：架構改為淺角度助推滑翔

**問題由使用者從軌跡形狀看出來**：彈道段頂點超過 1,100 km，
但先行者的經驗是只需到卡門線高度，太空飛機就能靠乘波體效應開始滑翔。

這是一個**物理上的否證**，而且它證實了審查意見 3.2 的判斷 ——
分段代理模型不只是「敘事上不該稱為保守」，它產出的軌跡根本不可飛。

| | 舊：分段代理模型 | 新：淺角度助推滑翔 |
|---|---|---|
| 熄火角 | γ = 30.9°（最小能量解） | γ = 2.0° |
| 遠地點 | **1,130 km** | **107 km** |
| v_bo（L/D 2.0） | 6,406 m/s | 7,382 m/s |
| 設計點 | L/D 2.0 | **L/D 4.0** |
| 總質量比 | 13.5 : 1 | 13.2 : 1 |

新架構在同一個 L/D 下更貴，但舊架構的便宜是幻覺。把設計點提到
L/D 4.0（實用乘波體）之後，質量比與舊架構相當 —— **省下的 Δv 這次是真的**。

**為什麼數值檢查抓不到這個錯。** 每一個中間量都正確：最小能量公式對、
軌道元素推導對、Eggers 反解對、兩邊程式碼數值一致到機器精度。
錯的是**把它們組合起來的假設**。這類錯誤只有兩種方式會被發現：

1. 把結果畫出來，看形狀對不對（這次就是這樣發現的）
2. 用物理直覺檢查量級（1,100 km 對次軌道運輸而言明顯過高）

所以驗證段加了一項**形狀檢查**：遠地點必須小於 200 km。
那不是數值精度檢查，是「模型有沒有退回錯誤架構」的檢查。

## 第七部分：已知限制

1. **這些不是設計值。** 全部是一階概念設計層級的解析式，用於建立量級直覺
   與因子耦合關係。真實設計需要上升段軌跡最佳化、六自由度再入積分、
   氣動係數資料庫與結構熱分析。

2. **分段代理模型不是可行軌跡**（見 2.4）。`max()` 既非上界也非下界，
   先前「保守近似」的說法已收回。

3. **速度損失是輸入假設，不是算出來的**（見 2.5）。低估損失會經由指數放大
   成質量比誤差，這是概念設計最常見的系統性錯誤。

4. **上升段是示意曲線**（見 2.10）。本專案的重力轉彎積分器沒有通過入軌基準，
   因此不用於繪圖或驗證。

5. **熱負荷只有速度項的比值，沒有絕對值**（見 2.8）。`√ρ` 項被丟掉，
   等於假設密度相同。

6. **減速量級不是峰值過載**（見 2.9）。乘員與結構過載要由含阻力的
   再入積分得出。

7. **平衡滑翔解在 `v/v_c → 1` 時退化**（見 2.3、5.2）。頁面在 `v/v_c > 0.95`
   時發出模型適用性警示。

8. **Δv 預算不含上升段氣動阻力損失**（阻力損失典型 100–150 m/s，
   已併入 2.5 的「損失」輸入假設中，未單獨計算）。滑翔段本身**有**阻力 ——
   Eggers 正是以固定 L/D 描述升阻關係，只是高度簡化；其指數大氣假設在
   60 km 以上失準。

9. **球形地球、赤道半徑**（見 2.0），在中緯度航線上略微高估大圓距離。

10. **分段代理模型已被推翻**（見 2.4、6.4）。舊版的彈道段遠地點
    1,130 km，不是有翼載具的軌跡；現為 107 km。

11. **未經獨立驗證。** 本頁的數值與 `spaceport_analysis.py` 一致（相對差 0.00e+00），
   但兩者共用同一套假設 —— 一致不等於正確。
